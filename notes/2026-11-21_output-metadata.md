# 出力とメタ情報（描画用リポジトリとの受け渡し）

## 描画は別リポジトリにし，CSV でやり取りする — 検討中（方針は合意）

- **[利用者]** CSV を描画して確認する Jupyter notebook は別のリポジトリに分け，CSV でやり取りしたい．
- **[Claude]** 賛成．Rust の CI に Python の依存を入れずに済み，notebook の差分でコードのレビューが埋もれない．
  ただし受け渡す前に，CSV がどの実行のものかを追えるようにする必要がある．
  - notebook 側は jupytext（`.py` と対にする）か nbstripout で出力を落としてコミットすると，差分が読める．
  - 生の CSV は今どおりこのリポジトリの logs/ に置き，notebook 側はパスで参照する．
  - 事後サンプルや当てはめ曲線を描くなら，CSV への出力を足す必要がある（未着手）．

## メタ情報はフォルダ＋YAML にする — 実装済み（16525e9）

- **[利用者]** メタ情報の量しだいで，CSV に埋め込むか，フォルダを作って YAML に書くかを決めたい．
- **[Claude]** デモのメタ情報は約 40 個あり（出どころ 6，データ 13，モデル 2，事前分布 5，`Config` 11，K ごとの要約），
  真のピーク列や K ごとの要約のように入れ子になる．ピークの形・Shirley 背景・実データの入力ファイルで今後も増える．
  コメント行での埋め込みは向かないので，実行ごとのフォルダに `meta.yaml` を置く．
- **[利用者]** JSON より YAML．
- **[Claude]** YAML は依存クレートなしで手書きする（書き出すだけなので）．serde_yaml は 2024 年から保守されていない．
  読み込み（設定ファイルとして使う）が必要になったら serde を入れることを相談する．
  - Python 側は PyYAML（`yaml.safe_load`）．YAML 1.1 の型推測の癖を避けるため，
    f64 は必ず小数点を含む 10 進表記，NaN/±∞ は `.nan`/`.inf`/`-.inf`，文字列はすべて二重引用符で囲む（`src/yaml.rs`）．
  - コミットハッシュと未コミットの変更の有無（dirty）は `build.rs` が git から取る．
  - `--out-dir DIR` で出力先を指定する．DIR に `meta.yaml` があれば上書きせずに止まる
    （作業用ディレクトリで実行し忘れて CSV を上書きした事故の再発防止）．
  - `Config` と `Prior` は `write_meta` で全フィールドを分解しているので，フィールドを足して書き忘れるとコンパイルエラーになる．
  - F_min・β̂ は `model_selection.csv` にあるので `meta.yaml` には重複させず，CSV にない交換率の範囲と実行時間だけを書く．
- 確認: 変更前（4d5263a）の 4 つの CSV とバイト単位で一致（K_max = 2，2000 スイープ）．
  PyYAML 6 で読み，int・float・bool・str の型がすべて意図どおりになることを確かめた．
