既定の引数で実行し，出力が標準出力や格子点の値と整合しているかを確かめる．

確認したこと（Python 標準ライブラリの csv で読んで計算）:

- `model_selection.csv` の σ̂ = 1/√β̂，ΔF = F_min − min_K F_min はすべての K で成り立つ（誤差 10⁻⁹ 未満）．
- `free_energy_fine.csv` は各 K で 201 点．両端（β_1 と β_max）の値は `free_energy.csv` の格子点の F と 10⁻¹¹ 以内で一致する．
- 補間曲線の最小は F_min より 0.01〜0.07 高い．曲線の点の間隔（対数で 0.058）では最小を挟みきれないためで，
  下の見積もり（(n/4)(0.029)² ≈ 0.06）と合う．

## 所見

- 3 つの CSV は互いに整合していて，PR #1 の出力に不具合は見つからなかった．
- **格子だけで選ぶと F_min を取り違える**: K = 4 では，格子での最小（β = 87.69 で −228.632）が F_min（−229.119）より 0.49 高い．
  隣の格子点は β = 109.93（−227.569）で，最小はその間にある．β̂ のまわりで F(β̂(1 + ε)) − F(β̂) ≈ (n/4)ε² なので，
  格子の比 1.25 程度（ε ≈ 0.08）でも n = 301 で約 0.5 nat ずれる．K の差（ΔF ≈ 0.5）と同じ大きさなので，
  モデル選択には格子の値ではなく `model_selection.csv`（`minimize_free_energy` の結果）を使う必要がある．
  補間曲線の最小も最大 0.07 ずれるので，描画用と割り切り，選択には使わない．
- K̂ = 4（ΔF(3) = 0.50，ΔF(5) = 0.49）．n = 301 では K = 3〜5 が決着しないという
  [n-scan](../2026-11-16_n-scan/README.md) の結果と同じ傾向で，新しい知見ではない．
- 事後平均の表示に使う格子点（β = 87.69）は，F が最小の格子点であり，β̂ = 95.27 に対数で最も近い格子点でもある．
