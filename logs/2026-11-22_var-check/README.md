# ⟨nE⟩_β の差分と Var(nE)_β の突き合わせによる交換の詰まりの検出（2026-11-22）

**目的**: Nagata くんの指摘「横軸を逆温度，縦軸をコスト関数の平均にとると，交換が起きていないところで挙動が変になる」を確かめる．
平衡なら d⟨nE⟩/dβ = −Var(nE)_β なので，隣接格子点の ⟨nE⟩ の差と，各スロットで測った分散から予測される差
−∫Var dβ を比べれば，「変な挙動」を数値で検出できるはず．

**コード**: 16525e9 と同じ内容をコミット前の作業ツリーで実行した（`meta.yaml` は `commit: 4d5263a…`，`dirty: true`）．
4d5263a に `--out-dir`/`meta.yaml` の変更と，`free_energy.csv` の末尾に `var_nE` 列
（本サンプリング全スイープの nE の分散，1/T で割る）を足す変更を加えた作業ツリー（`meta.yaml` は `dirty: true`）．
既存の 5 列は変更前とバイト単位で一致することを確かめた．

**実行**（10 スレッド．2 回実行して CSV がビット単位で一致することを確認）:

- `n101_ds1/`: `remc-spectral --out-dir … 5 20000 42 1 101 40`．[n-scan](../2026-11-16_n-scan/README.md) で交換率が 0.01 まで落ちた組．
- `n301_default/`: `remc-spectral --out-dir …`（既定の引数．交換がうまくいっている対照）

**解析**: `varcheck.py`（標準ライブラリだけ）．隣接格子点 l, l+1 の間で
比 = (⟨nE⟩_{l+1} − ⟨nE⟩_l) / (−∫_{β_l}^{β_{l+1}} Var dβ) を求める．Var は log β–log Var で線形補間（局所的にべき関数）して積分する．
平衡で格子が十分細かければ比は 1．出力は各フォルダの `varcheck.txt`（β ≥ 150 の区間と，全区間で比が最も 1 から離れた区間）．
CSV は `.gitignore` で除外されるので残らない．

## 所見

- 交換が詰まった 2 区間だけで，⟨nE⟩ の実際の落ち方が分散から予測される量の 3〜4 倍になった．
  交換率 0.3 以上の区間では比はほぼ 1（0.81〜1.11）で，交換の詰まりと比の異常が 1 対 1 に対応した．
  Nagata くんの言う「変な挙動」は ⟨nE⟩_β の段で，`var_nE` を使えば図を見なくても検出できる．
- K = 4 の β = 797, 916 では β² Var が 27.6, 75.3 と，ほかの β（5〜7.5．d/2 = 6 前後）より 1 桁大きい．
  エネルギーの分布が 2 つの山を持ち，スロットが 2 種類の配置（余分なピークの置き方が違う局所解など）の間を行き来している可能性がある．
- この比だけでは，次のどちらかは区別できない: (a) 交換が詰まって上下のレプリカが別の配置に閉じ込められた非平衡，
  (b) 平衡でも格子点の間で ⟨nE⟩ が急に変わる（相転移のような）変化を格子が分解できていない．
  どちらでもその区間の log Z の比（つまり高 β 側の F）の推定は信頼できないので，診断としてはどちらでも役に立つ．
  区別するには，その区間にレプリカを足す，MCMC seed やスイープ数を変えて ⟨nE⟩ が再現するかを見る．
- β̂ ≈ 96 の付近はどの K でも比が 1 に近く，F_min の推定には影響しない（mixing-diag の結論と同じ）．
- β² Var(nE) は実効的な λ の推定量でもある．n301_default では K = 1〜3 が 1.5, 3.0, 4.5 前後（d/2）で，
  n-scan で ⟨nE⟩ を 1/β に当てはめた λ̂ と合う．
